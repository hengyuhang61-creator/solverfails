Release engineering · redacted historical case

The tests passed. The installed app stayed old.

An October 2026 Personal OS handover reported 168 passing project tests and a successful candidate build. The installed desktop entry point still exposed the old build.

Probe the installed entry point

Use a synthetic version pair to replay the failure.

What happened

The handover reported successful candidate checks and an unchanged production build. It ended before the release switch or a test of the new build from the installed executable. Short performance samples left a possible slowdown unresolved.

What the evidence supports

The candidate had not reached the official entry point at that handover. The record reports no Windows permission error in that run. The result of a future attempted switch remains unknown.

Reproduce the release gate

node checks.mjs deployment stale
node checks.mjs deployment promoted

The stale fixture reports NOT_DEPLOYED (exit 1). The promoted fixture meets this version check (exit 0). For a real release, launch the installed entry point, read its build identity and exercise a core feature.

The private handover is summarized without paths, build identifiers or logs. The executable fixture is synthetic and makes no installation changes.
